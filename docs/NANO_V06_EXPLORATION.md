# Nano v0.6: controller-owned adaptive exploration

The project objective is a Nano-controlled AUV which adjusts its trajectory to
collect more thermal information near observed changes. The laboratory is a
replaceable environment/sensor/motion adapter. The decision algorithm belongs
to the controller, not the browser's free-swim planner.

## What runs where

| Part | Present implementation | Later physical replacement |
| --- | --- | --- |
| Adaptive decision | `firmware/auv_nano/Explorer.h` on the Nano | Same algorithm, validated/tuned for the vehicle |
| Offline controller | Exact same C++ header, compiled natively | Used for regression experiments |
| Probe reading | Delayed measurement generated by the lab | Characterized temperature probe driver |
| Position/velocity | Perfect simulated x, depth, vx, vz | Pressure/depth and a navigation estimate with quality/freshness checks |
| Motion | Nano requests surge/heave; lab integrates vehicle physics | Tested velocity/attitude controllers and calibrated thruster mixer |
| Thermal map | PC fits measurements along the resulting track | Onboard logging; optional topside analysis |

Free swim remains a separate browser demonstration. Choose **Adaptive exploration
· Nano / native controller** for this architecture. Length–depth only; tank width
and 3D volume coverage are not represented.

## Two-way bench loop

1. In Setup select Adaptive exploration, then Offline or Arduino Nano USB.
2. For Nano, Connect Nano and verify v0.6, simulated sensors, motors disabled.
3. Choose Sweep + small local cross-probes (or Sweep only as a baseline).
4. Use isolated warm spot, or choose a layer/front in Water structure. Water and
   probe settings now belong to the PC lab in this activity, even with Nano USB.
5. Run exploration. Live shows the board-requested target. Thermal maps shows
   the track, measured reconstruction, detour count and the last local 2D fit.
6. Stop ends the loop and sends STOP; Reset sends DISARM. Native exploration can
   pause. Nano exploration cannot pause: stopping observation delivery triggers
   its link timeout, so use Stop and restart instead.
7. Export CSV before Reset. CSV includes actual simulated x/depth, probe and
   reference temperatures, surge/heave requests, local/coverage phase, detour
   count, local-fit gradient/validity and mission exit code. Exact input time,
   input measurements/position/velocity, source and field parameters are included
   so each motion request can be aligned with the observation that caused it. `profile_x_m` is a
   legacy column alias for moving x in exploration; use `x_m` for new analyses.

The browser never sends truth temperatures, analytic gradients, spot coordinates
or a planned path to the controller. The PC bridge sends these measured inputs:

```
EXPL,adaptive,probe_tau_s
OBS,sequence,mission_ms,x_m,depth_m,vx_mps,vz_mps,probe_temperature_c
```

The board replies:

```
# EXP,sequence,active,local,reason,surge,heave,target_x,target_depth,gx,gz,gradient_valid,detours,coverage_waypoint
```

Spatial acceptance tests use 0.1 mm quantized coordinates to avoid branch
disagreements at floating-point/serial rounding boundaries on AVR and desktop.
This is numerical consistency, not a claim of physical positioning accuracy.

EXPL is allowed only with simulated sensors, motors disabled and profile
controller disarmed. OBS parsing is bounded to a 96-byte buffer, rejects
non-finite/out-of-range values and non-increasing mission time. The Nano stops
requests after 1 s without observations. The host correlates replies with sequence
numbers, rejects invalid output, and freezes the virtual plant if a reply is
missing for 1.5 s. It never advances by reusing an old board request. Profile
telemetry remains available for identity, but is not used as exploration data.

Mission reasons: 0 running, 1 survey complete, 2 mission budget, 3 invalid or
unordered observation, 4 operator stop/disarm, 5 observation-link timeout.
The controller's `gx,gz` are a fit from the latest local investigation, retained
on the following survey segment; they are not a current global gradient.

## What “just enough” means in this first controller

The broad baseline sweeps six depths, 0.2–2.7 m, between x=0.4 and 7.6 m.
During the survey, the controller compares probe readings after at least 0.15 m
of displacement. Two successive absolute temperature changes of at least
0.15 °C trigger a small local investigation. This is a finite-difference trigger,
not a second derivative or a PDE solver.

A local route crosses horizontally ±0.30 m and vertically ±0.20 m around the
observed candidate, clipped inside the bench domain, before rejoining its saved
survey waypoint. It accumulates least-squares sufficient statistics for
`T ≈ a + gx*x + gz*depth` with constant memory. It accepts a two-axis fit only
when sample geometry is sufficiently non-collinear. A cross ends after both
axes have been probed and that geometry condition is met, or after its six-target
route, or after 60 simulated seconds. At most three detours, separated by at
least 0.8 m from the preceding centre, fit within a 300 s mission budget.

Local nominal axis speeds are limited to `min(0.08, 0.10/tau)` m/s. This couples
motion to characterized probe response time and aims for an approximate 0.10 m
lag scale per axis. It is not a strict total-velocity error bound: simultaneous
axis motion, inertia and direction changes affect the actual lag. The probe is
initially equilibrated; free exploration currently has no random noise, currents
or navigation error. A real probe's tau must be measured; it is not known from
the ocean's temperature field.

Observation/recording rate remains nominally 10 Hz in simulated mission time.
Adaptation increases samples per metre through slower local motion and extra
passes, rather than pretending that a point probe observes an entire region.

This is an explicit first operational definition of sufficient *local geometric
sampling*, not a confidence certificate or guaranteed boundary-location accuracy.
A delayed probe biases the fit. Small spots between survey tracks can still be
missed. Sweeps retain exploration of quiet areas so a disconnected warm spot is
not dependent on a gradient leading to it.

## Deployment boundary

All physical ESC outputs remain compile-disabled. Explorer emits bench motion
requests; it does not drive the existing profile ESC routine. EXPL deliberately
cannot run with motors enabled. It uses the laboratory's 8 × 3 m domain, which
must not be confused with the existing vertical profile's 1.5 m safety envelope.

Replacing the lab with nature requires a real observation adapter, reliable
position/velocity estimates, sensor validity/freshness, leak/battery/attitude
interlocks, an independent abort strategy, tuned motion control and depth/geofence
limits for the actual vehicle. Temperature and pressure alone do not provide
horizontal position. These must be integrated and tested before removing the
bench-only restriction. A hull alone does not make this code field-ready.

## Build and evidence

Use this board's recorded standard bootloader (`cpu=atmega328`, 115200 baud):

```sh
bash tools/arduino.sh compile --fqbn arduino:avr:nano:cpu=atmega328 --build-path build/nano-v06 --build-cache-path /tmp/auv-arduino-cache firmware/auv_nano
bash tools/arduino.sh upload --fqbn arduino:avr:nano:cpu=atmega328 --port /dev/ttyUSB0 --input-dir build/nano-v06 --verify
```

v0.6 uses 21,822 flash bytes and 723 static RAM bytes, leaving 1,325 bytes for
stack/local allocations. This is a compile-time memory report, not measured
worst-case stack usage. Upload verification: `output/logs/nano_v06_upload.txt`.
The attempted old-bootloader upload failed before the standard setting succeeded.

C++ simulation, quiet-water, detour, two-axis-fit, slow-probe, time-budget,
invalid-input and sketch-command tests run through `bash tools/test.sh`.
`python3 tests/lab_test.py` includes 13 bridge tests and sequence/timeout checks.
`tools/verify_nano_exploration.py` exercises the actual board against the virtual
plant, compares every response with the native header on identical quantized
inputs, saves CSV/JSON, and disarms. Its virtual time advances as USB responses
arrive; it is a faster bench experiment, not a real-time underwater trial.

### Actual board verification completed

The final 21,822-byte build was flash-verified on the project Nano. The actual
board completed the isolated warm-spot mission in 173.1 simulated seconds with
2 detours, 488 local-phase rows and 1,732 correlated replies. All discrete
state/route decisions matched the native header on the same quantized inputs;
maximum surge/heave numeric difference was below 0.000052, and gradient
component differences below 0.000047. The complete accelerated USB experiment
took about 28 seconds of wall time. DISARM was acknowledged afterward.

Evidence: `output/logs/nano_v06_verified.json`, `nano_v06_exploration.csv` and
`nano_v06_upload.txt`. This proves the MCU owns the adaptive decisions against
the virtual plant; it does not validate physical underwater performance.

## Superseded trajectory policy

v0.7 replaces the dense sweep + crosses with sparse reconnaissance, local
along/across-feature moves, visitation-based candidate rejection and a total
travel budget. See [the current policy and comparisons](NANO_V07_BUDGETED_SAMPLING.md).
The v0.6 protocol and results above are retained as historical records.
